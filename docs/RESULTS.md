### Reading the monitoring column

A finding is not the same as detecting the breach. The reconciler looks for generic operational anomalies -- projection lag, drift, duplicate keys, orphans -- and is deliberately **not** told the aggregate ceiling, because giving the baseline that rule would make the silent-failure result circular.

P1, P2, P0 and P3 have no projector actor, so their events are never consumed and the reconciler correctly reports lag. That lag is unrelated to whether the money is right.

**S1 and S3 are the ones that matter.** Their projections caught up, so there is no lag to report, and the reconciler is fully clean while the business state is wrong by $100. That is the silent failure, measured.

## What the violations have in common

Every violating schedule shares four properties. Each action was:

- **authenticated** with a signed token the agent cannot forge or widen
- **authorized** by a policy the agent does not evaluate
- **idempotent**, keyed so a retry produces one effect
- **individually correct** given everything the actor could observe

And in every case, ordinary monitoring reported nothing.

## What separates P2 from S1

P2 is a timing race: both actors read before either wrote. Sequencing them fixes it, which is what P1 shows.

S1 is not a race. B reads **strictly after** A has fully committed and is wrong anyway, because the view it was given had not caught up. Sequencing does not fix it. S1C shows the only variable is whether the read model had caught up when consulted.

S3 rules out the comfortable reading that this needs a completely cold view: applying one of two pending events still breaches.

## What fixes both

P0 and S1H apply the same reservation primitive to the two different failure modes, and both stay clean. The reason is that the control service holds **authoritative** state rather than a derived view — S1H asserts B's projection was exactly as stale as in S1 and the outcome was still correct.

So the remedy is not a faster projection. A faster projection is still a projection.

## What this does not claim

Read-then-write across uncoordinated systems is textbook and predates this repo by decades. Nothing here is presented as a discovery. What is measured is the **combination**: that these failures survive proper authentication, proper authorization, idempotency, strict sequencing, and competent monitoring simultaneously.

Scope: two failure modes at one level of concurrency, in a harness whose schedules are deterministic by construction. Not a frequency estimate for any production system.
